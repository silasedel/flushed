# FLUSHED on Roblox — plan

The web version (this repo) is the design prototype. Roblox can't run HTML/JavaScript, so the
Roblox game is a rebuild in **Roblox Studio** using **Luau** (Roblox's scripting language). The
art, questions, answers, matching rules and scoring all carry over.

## 1. Crowd rarity (the big new feature)

**Goal:** every answer starts with the rarity we guessed (the curated scores in `data/questions/`),
and as real players answer, the tiers drift to what people *actually* say. Nobody plays against
anyone; the players just build the statistics together.

Reference implementation: [`js/crowd.js`](js/crowd.js) — simulate it with `node tools/crowd-sim.js`.

How it works, per prompt:

1. **Count.** When a player's answer is accepted, add 1 to that answer's counter (canonical name,
   not what they typed). One count per player per prompt per day, so spamming can't move it.
2. **Blend with the guess.** Each curated tier is a "pretend share" of players:
   NPC 20%, Mid 4%, Rizz 1%, Skibidi 0.2%, Sigma 0.05%. That guess counts as 300 pretend players:
   `share = (realCount + 300 × guess) / (realPlayers + 300)`.
   With no players the tiers are exactly the curated ones; after a few hundred players the real data dominates.
3. **Pick the tier from the share.**

   | Share of players who said it | Tier |
   |---|---|
   | 8% or more | NPC (10) |
   | 2%–8% | Mid (30) |
   | 0.5%–2% | Rizz (60) |
   | under 0.5% | Skibidi (85) |
   | the single rarest answer | Sigma (100) — always exactly one |

4. **No flicker.** An answer only changes tier once it's 25% past the line.
5. **Same rules for everyone each day.** Tiers are recalculated once a day (at the Daily Flush
   reset), not live, so everyone playing today's Daily is scored the same way.

Players could also see "**3% of players said this**" on the reveal once a prompt has enough players
(e.g. 200+). That's the real-statistics feel, and it costs nothing extra once we're counting.

Answers nobody has thought of yet (not in our list) are still rejected, but log them (privately,
for us to review) so the list grows with what players actually type.

### "How you stack up" curve
The results screen shows a score curve and "better than X% of flushers". On the web it comes from a fixed model of an
average player (`AVG_PROMPT` in js/game.js: 11% miss, 45% NPC, 25% Mid, 12% Rizz, 5% Skibidi, 2% Sigma per prompt).
On Roblox, keep a histogram of final scores per game length (5 / 7 / 10, and endless per prompt count) in DataStore,
and draw the real curve and percentile from it once there are a few hundred games; fall back to the model before that.

## 2. How it maps to Roblox

| Web prototype | Roblox |
|---|---|
| `data/questions/*.js` (~1,800 prompts, ~225k answers, ~6 MB) | Many **ModuleScripts** in `ServerStorage`, one per pack (split into chunks of ~200 KB). Generated by an export script from this repo — never typed by hand. |
| `js/match.js` (typos, plurals, aliases) | A Luau `Match` module — a line-by-line port. Runs **on the server** so players can't read the answer list or cheat. |
| `js/crowd.js` | A Luau `Crowd` module, run once a day by the server. |
| localStorage (streaks, stats, history) | **DataStoreService**, one key per player. |
| Answer counters | **MemoryStoreService** (fast counters shared by every server), written to **DataStoreService** every few minutes so nothing is lost. |
| Daily seed from the date | Same: the server uses the UTC date, so every server picks the same 7 prompts. |
| Canvas pixel art (`js/ocean.js`) | Sprites exported as PNG sprite sheets, uploaded as images, shown with `ImageLabel` + `ResamplerMode = Pixelated` so they stay crisp. The fall is a scrolling 2D GUI (same as now) or a real 3D sewer shaft the duck drops down. |
| HTML/CSS screens | `ScreenGui` + `Frame`/`TextLabel`/`TextBox`, built to match the web layout. |
| Fonts (IBM Plex Mono, VT323) | Roblox only allows its own fonts. Closest: **Code** / **RobotoMono** for text and **Arcade** for the logo. Or draw the logo as an image. |
| Web Audio synth sounds | Uploaded sound files. |

Recommended workflow: keep the Luau code in this git repo and sync it into Studio with **Rojo**,
so the question data and code stay versioned like they are now.

## 3. Roblox rules we must follow

- **Remove all hidden crude answers** (the ones starting with `!`) and any sexual or drug
  references. That includes the bedroom prompt's Sigma and some real song titles with swears.
  The export script should drop these automatically.
- **Text filtering.** Anything one player types that *other* players can see must go through
  `TextService:FilterStringAsync`. We only ever show **canonical answers we wrote**, never raw
  typed text, which keeps this simple. Don't add a feature that shows other players' raw guesses.
- **Experience Guidelines / maturity questionnaire.** Fill it out honestly; with the crude answers
  gone, this should be an all-ages experience.
- **DataStore limits.** Batch the counter writes (don't write on every answer).

## 4. Order of work when we start

1. Export script: questions → Luau modules (drops crude answers, splits by size).
2. Port `match.js` and `crowd.js` to Luau, with the same test cases (`tools/test.js`, `tools/crowd-sim.js`).
3. Server: daily seed, answer checking, counters, nightly re-tier, player saves.
4. Client UI: title, prompt card + answer box + timer, reveal, results.
5. Art + sound upload, then the fall animation.
6. Test with friends, then publish.
